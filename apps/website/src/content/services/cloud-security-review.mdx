A cloud review finds a lot in a short time, and it is easy to get approved internally, because it
cannot change anything.

You give us a role with read permissions. We assume it, list every account, subscription, project
and region, including the ones nobody remembers, and check the configuration against the published
benchmarks. Then we work out which of those findings chain together into a path from a
low-privileged identity to administrator.

## What usually comes back

Most small cloud accounts have the same four problems, and yours probably has at least two:

- A storage bucket that is public because a support tool needed it once.
- An IAM role that can pass any role to a compute service, which makes it administrator by another
  name.
- Access keys that have not been rotated since the account was created.
- Management logging switched on in one region only.

None of these is unusual. They are the reason most cloud incidents look the way they do. We report
each one with the exact command or console change that fixes it, ordered by how much risk the fix
removes rather than by benchmark number.

## The review is read-only by design

The role you grant has no write permissions, and the software that runs the review has no code path
that makes a write API call. You do not have to take our word for it: read the role policy we ask
for before you create it.

## Kubernetes

If a cluster is in scope we add benchmark checks against the control plane and nodes, an RBAC review
looking for paths from a pod to cluster administrator, and a check on network policy and pod
security standards.

The most common finding is that there is no network policy at all. That means every pod can reach
every other pod and the metadata endpoint, so compromising one pod compromises the cluster.

## When to buy it

Buy it on its own when your infrastructure has outgrown the person who set it up.

Buy it alongside a web application audit when the application and the cloud account are part of the
same risk. They usually are. An SSRF in the application plus an unprotected metadata endpoint is one
finding in the report and two teams in the room.

Many companies shipped a feature with a language model in it over the last two years. Fewer tested
it, and testing often meant running a prompt-injection list from 2024 against a system with
different failure modes.

Prompt injection has been first on the OWASP LLM Top 10 for two editions. An agent with tool access
can execute actions on your behalf, so the risk is closer to remote code execution than to a content
problem.

## You can buy this on its own

You do not need a web application assessment first. If what you have is a chat endpoint, a retrieval
assistant or an agent, we test that and nothing else.

It also works as an add-on to a web, API or mobile engagement when the model is part of a larger
product.

## What we test that a probe suite does not

Open-source probe suites are good and we run several of them. They give breadth cheaply. Four things
they do not cover:

**Indirect injection through your real ingestion path.** Not a payload typed into the chat box, but
one placed in a document your system retrieves, a web page your agent reads, a filename, an image
alt attribute or an API response. This is the highest-impact class for retrieval and agent systems,
and it depends on how your system is wired.

**Chained tool abuse.** Tools that are safe alone but not in combination. A read-only file tool plus
an email tool is a way to exfiltrate data. A generic suite cannot find this, because it does not
know what your tools do.

**Cross-tenant retrieval.** Using accounts in two separate customer organisations, we check whether
your retrieval filter applies on every path, including summarisation, citation and follow-up
questions. Those are often three different code paths.

**Measured success rates.** A jailbreak that works once in fifty attempts is a different finding
from one that works thirty-four times in fifty. We repeat every bypass and report it as a rate, with
the full conversation transcript as evidence.

## Cost abuse

Unbounded output, recursive prompting and expensive tool loops are a real risk, and we report the
finding in currency rather than in severity words.

We measure it under a spending ceiling that you set and confirm in writing before the run, and we
stop well below any figure that would matter. The aim is to tell you what an attacker could cost
you, not to demonstrate it.

## Clean-up

Anything we inject — a poisoned document, a memory entry, a record — is tracked and removed at the
end of the engagement. We verify removal by querying for it again. A planted document left in a
production corpus would be a live vulnerability we created.
